# LOG — decisions made while building gtmtakes.here

Newest at the bottom. Each entry: what was decided, and why.

1. **App lives in `gtmtakes/`, not the repo root.** This repo is the GitHub profile repo (its README renders on the profile page). Putting a Next.js app at the root would bury that. On Vercel, set Root Directory to `gtmtakes`. All paths in the brief (`/scripts/fetch_takes`, `/output/weekly.md`, PLAN/LOG/DONE) are relative to `gtmtakes/`.
2. **No `.env`, no `X_BEARER_TOKEN`, no `ANTHROPIC_API_KEY` in this environment.** So the pipeline is built with both paths (X API and CSV import), but only the CSV path could be exercised here.
3. **Seed takes must be real.** Posts were found by web search and each one verified against X's public embed endpoint (`cdn.syndication.twimg.com/tweet-result`), which returns the post text and author. Nothing in the seed was typed from memory.
4. **Turned off `cacheComponents` in next.config.** Every page reads live vote counts; the older `dynamic = "force-dynamic"` model is simpler and has no stale-split risk.
5. **SQLite via better-sqlite3 locally, Postgres via `pg` when `DATABASE_URL` is set.** One small adapter, portable SQL (`?` placeholders rewritten to `$n`), dates stored as ISO text in both. The Postgres dialect is tested against PGlite (real Postgres compiled to WASM) since no Postgres server was assumed.
6. **One vote per browser per take, final.** A repeat vote from the same cookie returns the original choice instead of changing it. On top of that, at most 5 votes per take from one hashed IP (`MAX_VOTES_PER_IP`). A strict one-per-IP rule would lock out offices and mobile carriers sharing an address; 5 stops the obvious "clear cookies and vote again" loop. IPs are stored only as a salted SHA-256 hash.
7. **Voting is open only on the take's own day** (site timezone, default America/New_York, `SITE_TZ`). After midnight the day's results are final, which is what makes an "end-of-day results" page and a weekly export meaningful.
8. **Author and source are hidden until you vote**, then shown with the split. People should react to the idea, not the name. Credit and link appear after every vote and on every results, archive, leaderboard and take page.
9. **"It depends" voters sit out the Hot/Not split.** 62% Hot means 62% of people who picked a side. The share who said "it depends" is shown separately.
10. **Divisiveness = 1 - |hot - not| / (hot + not)**; 1 is a perfect 50/50. Rankings use that number multiplied by `votes / (votes + 20)`, so a 1-1 tie cannot outrank a 240-260 split. Side effect: among takes with few votes, a 54/46 with more votes can edge out a 47/53 with fewer. This fades as vote counts grow. "Most agreed" and "most rejected" use a Wilson lower bound for the same small-sample reason.
11. **Learning model is deliberately simple.** For every topic and phrasing feature (absolute claims, comparisons, predictions, prescriptions, negative framing, names a tool, has a number, calls out a role, length), it keeps a vote-weighted average divisiveness, shrunk toward the overall mean. A candidate's predicted divisiveness is the mean plus its topic lift plus its average phrasing lift. Ranking adds a small exploration bonus for features with little data, and uses the LLM's debate estimate as a weak prior. With tens of takes, anything fancier would be fitting noise. Phrasing features are regex-based, so they are cheap and explainable but crude.
12. **Lineups are varied on purpose:** at most 3 takes per topic and 1 per author per day, relaxed only if the pool is too small.
13. **If nobody schedules a day in /admin, the site schedules it itself** from the approved pool, best-ranked first, the first time someone loads the home page. An empty site is worse than an unreviewed order, and only already-approved takes can be picked.
14. **Seed votes are generated, and labelled as such.** A working results page, leaderboard, export and learning loop need votes, and there are no real voters yet. Seed votes are stored with `source = 'seed'`; while any exist, the site footer and the top of `output/weekly.md` say so. `npm run seed:clear-votes` removes them; `npm run seed -- --no-votes` never creates them.
15. **The LLM step for the 72 seed takes was done by Claude in the build session**, not through the API (no key here). Each statement was written against the post text returned by X. 43 of the 72 posts are long-form posts that X's embed endpoint cuts at about 280 characters, so those rewrites are based on the opening of the post. Statements only restate claims visible in that opening.
16. **LLM step in code uses the Anthropic SDK with structured output**, model `claude-opus-5-5` (override with `TAKES_MODEL`). If the model returns no verdict for a post, the post goes to the review queue marked for manual review instead of being guessed at. Without `ANTHROPIC_API_KEY` the script falls back to a keyword filter that cannot rewrite; those candidates say so in /admin.
17. **CSV import can look posts up by URL** using X's public embed endpoint (the one embedded posts load from; no key). It is unofficial and could change or be rate-limited, so the CSV also accepts the text directly.
18. **"gtmtakes.here" is treated as the brand name.** `.here` is not a registrable top-level domain, so links use `NEXT_PUBLIC_SITE_URL` and the name appears as text on cards and in the header.
19. **Admin auth is a single shared password** in an httpOnly cookie (a hash derived from the password). Enough for one editor; not multi-user.
